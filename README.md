# 栖居 · 可交互三维家庭

独立的 Three.js + Vite 前端项目，按提供的户型图建立三室一厅、厨房、卫生间、储物间、过道及阳台。

## 运行

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开终端提示的本地地址。构建与验证：

```bash
npm test
npm run build
npm run preview
```

`dist/` 可部署到普通静态服务器，不依赖后端。

## 部署

线上地址：<https://pircate.github.io/home-atlas/>

```bash
npm run deploy
```

脚本会跑测试、以 `--base=/home-atlas/` 构建，再把 `dist/` 推到 `gh-pages` 分支。

项目页位于子路径下，直接 `npm run build` 的默认 `base` 会让资源 404，因此须用 `npm run build:pages` 或 `npm run deploy`。

## 操作

- 拖动旋转、滚轮缩放、右键平移；触屏单指旋转、双指缩放和平移。
- 房间导航定位、三维与俯视切换、视角重置。
- 相机视线被墙体遮挡时自动渐隐；支持隐藏全部墙体和完整墙体。
- 点击家电实体或设备列表打开独立控制菜单；移动端用「设备」按钮打开列表。
- 24 个设备，其中 14 盏独立灯光，客厅 3 盏、每间卧室 2 盏。
- 每盏灯有开关、亮度和色温，控制真实渲染光源与阴影；支持日间和夜晚。
- 空调温度和模式、电视屏幕、洗衣机启停与滚筒动画、音箱音量、其他电器电源。
- 归家、松弛夜晚、离家场景；设备设定保存在当前浏览器。
- 布置模式：点工具条末尾的移动图标开启，之后点选家具拖动换位置、捏住圆环上的手柄旋转，也可用方向键微移、Q/E 旋转；家具摆位与设备状态一起存在当前浏览器，「恢复默认摆放」一键还原。

## 依据与限制

根据对话提供的户型图建模，优先保留房间净尺寸和邻接关系，墙高设为约 2.65 米，门窗细节为估计。顶部采用无天花板剖切展示。

布置模式把家具按套分组（床连床头柜、餐桌连餐椅），移动范围限制在各房间地面的并集内，允许跨房间搬动，但不做家具与家电之间的碰撞检测，也不做跨房间寻路，因此家具可以在不经过门洞的情况下换房间。台灯、电视、电磁灶这些摆在家具上的电器会随家具一起移动旋转，它们的安装高度固定在墙上的家电（吸顶灯、空调、油烟机、热水器）则不可移动。卫生间净宽只有 1.59 米，洁具转不开身，因此不提供旋转。

地毯是贴地薄片，并入床组或沙发组会把包围盒撑到 2.7 米以上、在卧室里再也转不开，故作为不可移动的固定装饰。

储物间按另一张布局图改作了电竞房：西南自行车停车柜（柜内立挂一辆公路车）、西北衣柜（柜门朝东）、东北电竞桌椅（桌 1.36×0.75 贴北墙靠东，椅子在桌下 x≈1.35）。布局图给的净宽是 1.90 米，而这里建出来的净内宽是 1.85 米（西墙内面 x=0.065，东墙内面 x=1.915），所以桌子比原图窄了 4 厘米、衣柜与桌子之间的走线缝从 10 厘米收到 2 厘米才放得下。

家具拾取用真实几何而非包围盒：桌椅组的包围盒会把椅子周边和桌子上方的空隙一并占满，从储物间默认机位看过去会挡住后面的衣柜，点衣柜反而选中桌子。

厨房按开放式处理：原本封住厨房南面、把厨房和客厅隔开的那道墙（z=2.57，连同西侧 14 厘米门垛）不砌了，只在原墙位留一段岛台——柜体从旧门洞东侧 x=7.82 一直连通到东侧橱柜，台面与东侧同高、边缘对齐，两段拼成 L 形。0.83 米宽的门洞位置不变，仍是从客厅进厨房的通道。岛台进深 0.54 米，比原来 0.13 米厚的墙宽得多，必然两侧都探出来：南沿收到 z=2.77，为的是让客厅绿植（8.63,3.11）最北那片叶子（约 z=2.83）不至于穿出台面。岛台与墙一样是固定构件，不参与布置模式的拖动与旋转。

尚未收到实拍图，家具、家电位置、数量及材质为设计示意，不能视为实景复刻或施工模型。原始临时图片已被清理，未包含在此项目中。

所有家电控制均为本地模拟，未连接真实设备。功率为模拟额定估算，冰箱温度为固定展示，音箱不播放音频。刷新后洗衣机不会自动恢复洗涤。

## 代码

- `src/model.js`：几何、材质、灯光、相机、拾取与墙体避让。
- `src/state.js`：房间、设备、场景和状态恢复。
- `src/main.js`：界面与交互。
- `src/style.css`：桌面与移动端样式。
- `src/state.test.js`：状态测试。

参考 [Three.js 官方文档](https://threejs.org/docs/)。几何和纹理均由本地代码生成，无远程模型及字体依赖。
