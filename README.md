# 栖居：可交互三维家庭

独立的 Three.js + Vite 前端项目，按同一套房源的如视（贝壳）VR 实测数据建立三室一厅、厨房、卫生间、储物间、过道及阳台。

## 运行

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开终端提示的本地地址。构建与验证：

```bash
npm test
npm run build
npm run preview
```

`dist/` 可部署到普通静态服务器，不依赖后端。

## 部署

线上地址：<https://pircate.github.io/home-atlas/>

```bash
npm run deploy
```

脚本会跑测试、以 `--base=/home-atlas/` 构建，再把 `dist/` 推到 `gh-pages` 分支。

项目页位于子路径下，直接 `npm run build` 的默认 `base` 会让资源 404，因此须用 `npm run build:pages` 或 `npm run deploy`。

## 操作

- 拖动旋转、滚轮缩放、右键平移；触屏单指旋转、双指缩放和平移。
- 房间导航定位、三维与俯视切换、视角重置。
- 相机视线被墙体遮挡时自动渐隐；支持隐藏全部墙体和完整墙体。
- 点击家电实体或设备列表打开独立控制菜单；移动端用「设备」按钮打开列表。
- 21 个设备，其中 11 盏独立灯光，客厅 2 盏、厨房及岛台 2 盏、每间卧室 1 盏。
- 每盏灯有开关、亮度和色温，控制真实渲染光源与阴影；支持日间和夜晚。
- 空调温度和模式、电视屏幕、洗衣机启停与滚筒动画、音箱音量、其他电器电源。
- 归家、松弛夜晚、离家场景；设备设定保存在当前浏览器。
- 布置模式：点工具条末尾的移动图标开启，之后点选家具拖动换位置、捏住圆环上的手柄旋转，也可用方向键微移、Q/E 旋转；家具摆位与设备状态一起存在当前浏览器，「恢复默认摆放」一键还原。

## 依据与限制

户型不再是手抄户型图，而是按同一套房源的**如视（贝壳）VR 实测数据**重建：9 个房间、39 段墙体中线、18 处门窗洞口（10 樘门含入户门与阳台推拉门，8 樘窗，其中 4 樘低窗台 0.10 米、4 樘窗台 0.95 米）。顶部采用无天花板剖切展示。

数据里**哪些是拟合实测、哪些是算法模板**要分清：房间多边形、墙体位置和窗洞宽度是点云拟合的原始值（窗宽会出现 1.695670 米、2.916292 米这种没取整的尾数）；而门洞宽度、墙厚和层高是统一模板——10 樘门里 8 樘正好 0.800 米、门高一律 2.0 米，40 面墙的顶标高一律 2.7 米、厚度一律 0.12 米（内外墙不区分厚度）。所以这里的房间划分、开间进深和门窗位置可信，但门洞净宽、墙厚、层高不宜直接拿去下门套或定制柜体，那几项仍需现场复核。

面积有两种口径，页面上用的是前者：**各房间净面积合计 72.7 m²（不含墙体，即 VR 报的 room size）**；按墙中线多边形统计则是 79.4 m²。地面薄板按墙中线多边形铺，相邻房间在墙中线处严丝合缝、墙体正好压在接缝上。

数据管线（重建户型需要提供原始抓包 JSON，未随仓库保存）：

```bash
python3 scripts/build-layout.py /path/to/r002.json  # 原始户型 JSON → src/layout.js（自动生成）
python3 scripts/render-plan.py     # → output/实测平面图.png，用于和 VR 图纸比对
```

- 墙体取图纸的「点—线」模型，端点正好落在房间多边形边界上，也就是墙中线；不能用 `edgeWall` 的板外形，那是把 12 厘米厚度斜切出来的六边形，包围盒会比真墙长一截。
- 洞口取 `edgeWall` 的 `holes`（带精确范围与窗台高／过梁高），再把「墙法向」坐标吸附到**与它在墙方向上真正重叠**的那面墙上——只按最近距离吸附会把卫生间门吸到十几米外的厨房那面墙上（两面墙的 z 只差 1.8 厘米）。
- 洞口吸附保留 4 位小数。少一位就会和墙中线差 0.1 毫米，门洞闸门盖不住墙体阻滞带，会在门边留一条过不去的发丝缝。

布置模式把家具按件或按套分组（如岛台连吧椅），移动范围限制在各房间地面的并集内，允许跨房间搬动，但不做家具与家电之间的碰撞检测，也不做跨房间寻路，因此家具可以在不经过门洞的情况下换房间；能不能站立、能不能穿墙由墙体和洞口决定。电视、电磁灶这些摆在家具上的电器会随家具一起移动旋转，固定装在墙面或天花板上的家电（吸顶灯、空调、油烟机、热水器）则不可移动。淋浴房保留固定朝向，马桶与外置洗手台可独立移动和旋转。

客厅地毯作为不可移动的固定装饰，不计入沙发的移动边界；卧室 B 不铺地毯。

保留已确认的装修布局，并按实测房间的墙内边界调整坐标：

- 卧室、储物间、客厅、厨房与过道按实拍参考通铺暖红棕长条木地板，深褐波浪山形木纹、错缝直铺、透明漆面柔光；板幅按约 15×120 厘米示意，并非实测尺寸。纹理按全屋坐标连续铺贴，卫生间保留浅色砖，阳台保留深灰砖。
- 卧室 A、B、C 的衣柜与卧室 B 吊柜统一为白色柜体和柜门，搭配浅灰门缝与金属拉手。
- 卧室 B 的床垫长 2 米、宽 1.8 米，床头朝西、床侧贴南窗，不铺白色地毯。卧室 C 改为长 2 米、宽 1.2 米的单人床，侧面靠西墙，床头朝南（图下方）、靠南窗，不设床头靠背。两间均不放床头柜和台灯；北墙衣柜避开门洞及门扇，卧室 B 上方吊柜保留 2.18 米净高，卧室 C 门洞上方留空。两间卧室空调均挂西墙、朝东出风。
- 卧室 A 的床垫长 1.8 米、宽 1.5 米，床头朝西、床侧贴北窗；西南角沿西墙放长 1 米的衣柜，柜门朝东。床架和床头板另占少量空间。
- 厨房按效果图保留开放式：北墙水槽台与东墙灶台组成 L 形橱柜，冰箱位于东侧灶台南端、向西开门。独立白台面岛台配南侧两把吧椅，替代圆餐桌，岛台两侧留通道。原始墙体数据保持不变，厨房南墙及西墙南段在 `src/state.js` 的 `REMOVED_WALLS` 中声明，建模与家具边界约束共用这份清单。
- 储物间北窗下放木色电脑桌椅，西墙为长 211 cm、高 220 cm、深 37 cm 的古铜色洞洞板车架，靠西、南两面墙放置；黑色底座，上层横挂青绿色公路车，下层放橄榄绿公路车与骑行台，两辆车车头均朝北，南端挂头盔、眼镜及手套。车架避开东侧门扇开启范围。
- 客厅东墙放深灰沙发及南端边柜，西侧放电视与绿植长柜，中间为绿米条纹地毯、白色圆茶几及木色边几；北侧奶油色圆壳椅朝南，南侧橄榄绿扶手椅朝向茶几，通往阳台的西侧通道保留。
- 卫生间门内为北侧淋浴区与东侧马桶，洗手台和镜子移至门外东侧凹位；门扇改为西侧铰链向内开启，避开马桶。外置洗手台在导航中属于过道，可独立移动。
- 过道（7.63 m²）在实测数据里是一块连通区域，包含入户玄关和通往各房间的走廊，因此合成一个房间；入户门在北墙 x 6.16~6.96。客厅与过道之间保留门洞，不装门扇；客厅与过道门洞以及三间卧室、储物间的门洞下均不做门槛。

`vr/furniture-items.json` 保留原房源的四件扫描家具足迹作为参考。装修方案的床宽、朝向和厨房布局以本项目已确认方案为准，不直接套用原房源的家具足迹。家具、家电和材质为设计示意，不能用作施工图。

房屋坐标更新后，旧家具摆位及旧设备位置不再套用，浏览器将显示新的默认布置。

所有家电控制均为本地模拟，未连接真实设备。功率为模拟额定估算，冰箱温度为固定展示，音箱不播放音频。刷新后洗衣机不会自动恢复洗涤。

## 代码

- `src/plan.js`：旧版按图纸估算的户型参考，运行时已改用 `layout.js`。
- `src/model.js`：几何、材质、灯光、相机、拾取与墙体避让。墙体与洞口全部按 `layout.js` 数据生成（装修方案拆掉的墙段由 `state.js` 的 `REMOVED_WALLS` 排除），不手写坐标。
- `src/layout.js`：**自动生成**。房间多边形、墙体中线、门窗洞口表，数据源见「依据与限制」。
- `src/state.js`：房间、家具默认摆位、设备、场景和状态恢复；墙体阻滞与门洞通行判定也在这里。
- `src/main.js`：界面与交互。
- `src/style.css`：桌面与移动端样式。
- `src/state.test.js`：状态测试，含墙洞连通性、家具摆位与墙体数据完整性校验。
- `scripts/build-layout.py`：把 VR 抓到的户型 JSON 转成 `src/layout.js`。
- `scripts/render-plan.py`：出 `output/实测平面图.png`，用来和 VR 图纸比对。
- `vr/floorplan.json`：该房源 VR 的元信息（workCode、unionPlanCode）。

参考 [Three.js 官方文档](https://threejs.org/docs/)。几何和地毯纹理由本地代码生成，地板使用随项目打包的 `src/assets/wood-floor.png`（依据用户实拍参考，由内置 imagegen 生成）；无远程模型及字体依赖。
